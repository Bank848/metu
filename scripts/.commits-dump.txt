===HASH:491007a===
===SUBJ:fix(phase-33c): atomic stock decrement on checkout===
Concurrent buyers racing for the same physical-style variant could
both place orders, leaving product_item.quantity negative. Wrap the
decrement in a conditional updateMany inside the existing checkout
transaction:

  UPDATE product_item
     SET quantity = quantity - :n
   WHERE product_item_id = :id
     AND quantity >= :n;

If the update returns 0 rows the second buyer hit the depleted state
and we throw 409 OutOfStock, rolling the whole transaction back. The
"check-then-decrement" race window is gone because Postgres serialises
the WHERE quantity >= :n predicate inside row-level locking.

Digital delivery methods (download, email, license_key, streaming)
skip the decrement -- their quantity field tracks pre-generated keys
or is conceptually infinite.

    amount-mismatch) so callers can branch into auto-credit vs
    queue-for-admin paths cleanly.

decode time per slip. Every modern Thai bank slip ships with a
structured QR — reading it via jsqr is fast + deterministic, and

===SUBJ:fix(qa-r3/F1): suppressHydrationWarning on <html> for theme-bootstrap script===
QA round #3 caught two minified React errors firing on every public
page (/, /browse, /product/[id], …) but NOT on routes that bypass the
ProductCard grid (/seller, /login, /health):

  React error #418: hydration failed (HTML didn't match)
  React error #422: Suspense boundary error during hydration

Root cause: app/layout.tsx mounts a `themeBootstrapScript` in <head>
that runs synchronously BEFORE React hydrates. The script reads
localStorage and rewrites `<html>`'s className from "...dark" to
"...light" when the user has saved the light theme. On hydration,

rendering the affected boundary) but the warnings are loud and the
fallback costs perf.

flag scopes to that element only — child trees still hydrate
strictly. This is the standard Next.js theme-toggle pattern (cf.
next-themes), telling React that the discrepancy on this element is
intentional and the bootstrap script is the source of truth.

The bootstrap script itself is unchanged — kills flash-of-wrong-
theme on hard reload, which is the right tradeoff.

===SUBJ:chore(deps): bump next 14.2.18 → 14.2.35 for security patches===
The deprecation warning during npm install pointed to the
2025-12-11 advisory (https://nextjs.org/blog/security-update-2025-12-11).
14.2.35 is the latest patch in the 14.2 line and rolls up several
intermediate CVEs (middleware bypass, cache poisoning, etc) without
any breaking changes vs 14.2.18.

A handful of high-severity advisories still affect the entire 9.x–15.x
range; the only 'fix' npm audit suggests is jumping to next@16, which
is a major version bump (React 19, App Router behaviour changes) that
we deliberately defer until after the in-class presentation.

For our demo on Vercel, the residual advisories are not exploitable:
- next/image disk-cache growth → we use unoptimized everywhere
- remotePatterns DoS → only matters self-hosted; Vercel autoscales
- HTTP request smuggling in rewrites → we have no rewrites
- RSC DoS → low-traffic demo behind a class-only audience
